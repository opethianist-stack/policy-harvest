# 승인 시트·드라이브 업로드 설정 (Apps Script)

부서 공통 gmail 계정이 소유한 구글 시트에 Apps Script를 붙인다. 스크립트는 부서 계정 권한으로 실행되며 두 가지를 한다.

- 수집기(GitHub Actions)가 보낸 행을 시트에 추가한다(`doPost`)
- 매일 01:00에 승인 칸이 체크된 행의 원본 파일을 받아 정책문서 폴더에 파일명 규칙대로 저장한다(`deliverApproved`). Policy Fit은 03:00에 폴더를 색인한다

구글 클라우드 프로젝트·OAuth 앱 게시·토큰 발급은 필요 없다.

## 1. 시트 만들기 (부서 계정)

1. 구글 드라이브에서 새 스프레드시트를 만든다. 이름 예: `policy-harvest 승인`
   - 정책문서 폴더 **밖**에 둔다
2. 메뉴 **확장 프로그램 → Apps Script**
3. 편집기의 `Code.gs` 내용을 모두 지우고, 레포의 [`apps-script/Code.gs`](../apps-script/Code.gs) 내용을 그대로 붙여 넣는다 → 저장
4. 편집기 왼쪽 **서비스 +** → `Drive API` 선택 → 추가. 과기정통부 보도자료처럼 odt만 올라오는 첨부를 PDF로 바꿔 저장할 때 쓴다(구글 문서로 변환한 뒤 PDF로 내보내고, 임시 문서는 휴지통으로 보낸다)

## 2. 처음 실행

1. 편집기 위쪽 함수 선택에서 `setup` → **실행**
2. 권한 검토 창 → 부서 계정 선택 → "Google에서 확인하지 않은 앱" 안내가 나오면 **고급 → policy-harvest(으)로 이동** → 허용
   - 요청 권한: 스프레드시트, 드라이브(정책문서 폴더에 파일 저장), 외부 서비스 연결(원본 파일 다운로드), 트리거
   - 본인 계정의 본인 스크립트라 검수 대상이 아니다
3. 실행 로그에 `수집기용 TOKEN: …`이 나온다. 이 값을 복사해 둔다
4. 시트에 `inbox` 탭과 머리행이 생기고, 매일 01시 `deliverApproved` 트리거가 등록된다(편집기 왼쪽 시계 모양 메뉴에서 확인)

## 3. 웹 앱 배포

1. 편집기 오른쪽 위 **배포 → 새 배포**
2. 유형 선택(톱니바퀴) → **웹 앱**
   - 실행 계정: **나**(부서 계정)
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - 누구나 호출할 수 있지만 TOKEN이 맞지 않으면 거절하고, 할 수 있는 일은 시트에 행을 추가하는 것뿐이다
3. 배포 → 웹 앱 URL(`https://script.google.com/macros/s/…/exec`)을 복사

## 4. GitHub Secrets 등록

레포 **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `SHEET_WEBHOOK_URL` | 3에서 복사한 웹 앱 URL |
| `SHEET_WEBHOOK_TOKEN` | 2에서 복사한 TOKEN |

값은 채팅이나 레포 파일에 붙이지 않는다.

## 코드를 고쳤을 때

1. 레포의 `apps-script/Code.gs`를 편집기에 다시 붙여 넣고 저장
2. **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**. 이렇게 하면 웹 앱 URL이 바뀌지 않는다(새 배포를 만들면 URL이 바뀐다)
3. 새 권한이 필요한 코드면 처음 실행할 때 권한 검토 창이 다시 뜬다. 편집기에서 아무 함수(예: `checkFolderNames`)나 한 번 실행해 허용해 두면 01시 트리거가 멈추지 않는다

## 수동 점검

- 편집기에서 `deliverApproved` 실행: 트리거를 기다리지 않고 승인 행을 바로 보낸다
- `checkFolderNames` 실행: 정책문서 폴더에서 파일명 규칙과 다른 파일을 로그에 남긴다

## 지정 번호 열

시도교육청 계획처럼 번호가 정해진 문서는 수집기가 `지정 번호`(예: 19-2)를 채운다. 이 행은 폴더 번호 다음 값 대신 지정 번호로 저장하고, 같은 글의 행이 여럿이면 `19-11-1`, `19-11-2`처럼 붙인다. 다른 행에도 번호를 직접 적으면 그 번호를 쓴다.

코드를 새로 붙여 넣은 뒤 처음 실행될 때 머리행 끝에 `지정 번호` 열이 생긴다.

## 검토 보기(필터)

시트를 열면 메뉴에 **수집기**가 생긴다(코드를 붙여 넣은 뒤 시트를 새로 고침).

- **검토할 행만 보기**: 추천이 `제외`가 아니고 상태가 `대기`이거나 `실패`인 행만 보이게 필터를 건다. 이 화면에서 필요한 행에 승인을 체크한다. 필터가 켜져 있으면 수집기가 새 행을 보낼 때도 다시 적용된다
- **승인 안 한 행 넘기기(검토 끝)**: 다 봤으면 실행한다. 승인하지 않은 `대기` 행을 `넘김`으로 바꿔 검토 보기에서 뺀다(행은 지우지 않는다. 분류 실패 `검토 필요` 행은 다시 분류되도록 남긴다)
- **전체 보기**: 필터를 끈다
- 넘긴 행을 다시 살리려면 상태를 `대기`로 바꾼다

## 분류 실패 행

분류 API 오류 등으로 분류하지 못한 글은 시트에 보내지 않고 다음 수집 때 다시 분류한다. 이 방식 이전에 올라온 `검토 필요` 행은 수집기를 `--reclassify`로 돌리면 다시 분류해 그 행의 추천·문서 유형·문서명 등을 고친다(승인하지 않은 `대기` 행만).

## 상태 열 읽는 법

| 상태 | 뜻 |
|---|---|
| 대기 | 승인 전이거나 다음 실행을 기다리는 중 |
| 중계 대기 | 구글 서버에서 받을 수 없는 사이트. 00:30 러너 중계 뒤 01:00에 저장된다 |
| 넘김 | 검토했고 승인하지 않음(검토 보기에서 빠짐) |
| 전송 완료 (시각) | 폴더에 저장됨. 파일명·드라이브 링크 열에 결과 |
| 실패: 저장하지 않는 형식 | pdf·hwpx·hwp·odt·xlsx·zip이 아님 |
| 실패: 다운로드 HTTP … | 원본 사이트가 막았거나 주소가 바뀜. 직접 받아 넣는다 |
| 실패: 압축 풀기 실패 | Apps Script가 풀지 못하는 zip(국가AI전략위의 (HTML)·(MD) 판 등). 같은 문서의 pdf 행이 있으면 승인하지 않는다 |
| 실패: 같은 이름 있음 | 폴더에 같은 파일명이 있다 |
| 전송 완료 (시각) (odt→pdf 변환) | odt를 PDF로 바꿔 저장했다. 원본 형식이 아니므로 필요하면 원문 링크로 대조한다 |
| 전송 완료 (시각) (압축 풀어 N개) | zip 안의 파일 N개를 저장했다. 파일명·드라이브 링크 열에 줄바꿈으로 모두 적는다 |
| 전송 완료 (시각) (xlsx 원본 저장, 색인 안 됨) | 엑셀은 원본 그대로 두었다. Policy Fit이 엑셀을 읽기 전까지 검색되지 않는다 |
| 실패: 압축 안에 저장할 파일 없음 | zip 안에 이미지 등 저장하지 않는 형식만 있다 |

실패한 행은 원인을 고친 뒤 상태를 `대기`로 바꾸면 다음 실행에 다시 시도한다(승인 칸은 체크된 상태로 둔다).

## 해외에서 받을 수 없는 첨부(러너 중계)

과기정통부(www.msit.go.kr)·교육부(www.moe.go.kr)는 구글 서버(해외)의 접속을 받지 않아 Apps Script가 첨부를 받지 못한다. 대신 GitHub 러너가 받아 넘긴다. 목록에 없는 사이트도 받기에서 `Address unavailable`(사용할 수 없는 주소)이 나면 그 행을 `중계 대기`로 바꿔 같은 방식으로 받는다.

1. `relay` 워크플로(매일 00:30 KST)가 시트에 승인된 중계 대상 행(과기정통부·교육부의 `대기` 행과 `중계 대기` 행)을 묻고, 첨부를 받아 웹 앱으로 보낸다
2. 웹 앱은 파일을 드라이브의 `policy-harvest 중계` 폴더(정책문서 폴더 밖, 처음 한 번 자동으로 생긴다)에 넣는다
3. 01:00 `deliverApproved`가 중계 폴더의 파일로 파일명 규칙대로 저장하고 중계 파일은 휴지통으로 보낸다. 상태에 `(러너 중계)`가 붙는다

중계 파일이 아직 없는 행은 `대기`·`중계 대기`로 남고 번호도 잡지 않는다. 낮에 승인한 중계 대상 행을 바로 넣으려면 GitHub **Actions → relay → Run workflow**로 중계를 돌린 뒤 시트 메뉴 **승인 행 지금 보내기**를 누른다.

## 실행 시간 한도

한 번 실행은 6분에서 끊기므로 4분이 지나면 멈추고 1분 뒤 이어서 돈다(`continueDelivery` 트리거가 잠깐 생겼다 사라진다). 어떤 사이트에서 접속 오류가 나면 그 실행에서는 같은 사이트의 남은 행을 건너뛰고 `대기`로 두어 다음 실행에 다시 시도한다.
